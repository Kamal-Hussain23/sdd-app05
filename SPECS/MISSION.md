# Mission

## Why this project exists

This is a **course project** built to learn web development. We are building a
simple cafe ordering system so customers can place an order and staff can see
it. The goal is to learn, not to run a real cafe, so we keep everything as
simple as possible.

## Who it is for

Two kinds of users:

- **Customers** — people who open the site, look at the menu, and place an order.
- **Staff** — people who see new orders arrive and mark them as ready.

## What success looks like

A customer can open the site, pick something from the menu, place an order, and
see it confirmed. On the other side, staff can see that new order appear and
mark it as ready. That simple loop working end-to-end is a success.

## Non-negotiable constraints

- **No database.** We have not learned databases yet. All data stays in memory
  while the server is running (a Python list or dict) and resets on restart.
- **No frameworks.** Vanilla HTML, CSS, and JavaScript only. No React or other
  libraries.
- **Simple over clever.** Prefer the most obvious solution.
- **Build from a written spec.** Every feature starts as a requirements/plan/
  validation spec before any code is written.

## Out of scope

- Accounts, logins, or user identity.
- Payments or money.
- Persistent storage or "save" features.
- Real menu / inventory management.
